# Fidel Telegram (easy, classical, dynamic file generator)

**Concept:** a classical cipher written in Ge'ez script (fidel).

## Mechanics
- Each printable ASCII character maps to a cell of the fidel grid: `idx = ord(c) - 32`, `row = idx % 31`, `order = idx // 31`.
- The row is encrypted with an affine cipher mod 31: `row' = (a * row + b) % 31`.
- The vowel order is encrypted with a repeating Vigenère key mod 7. The key is 5-8 entries long.
- The output is rendered as Unicode fidel (`ROWS[row'] + order'`).

## Intended solve
Players receive their personalized `message.txt` generated by the platform.
1. Split each fidel into consonant + vowel form.
2. Every crib letter in `TELEGRAM` (given in the description) has the same plaintext order, so its cipher orders give the order key directly. The key repeats after its length (5-8). Confirm the period on the body: the correct period leaves about 2 distinct orders per column.
3. Undo the order shift per column. Each (consonant, order) pair is now a fixed letter, so solve the rest as a monoalphabetic substitution, starting from the crib letters.
4. `_` is the only unseen consonant inside the flag and is obvious from context.

## On-Demand Dynamic File Generator (Platform Settings)

This challenge supports the platform's **On-Demand Dynamic File Generator** to generate personalized challenge files with participants' unique dynamic flags.

### Platform Configuration
- **Enable Dynamic Generator**: `[x] ENABLED`
- **GENERATOR DOCKER IMAGE**: `ghcr.io/azariyasmekonen/fidel-telegram:latest`
- **OUTPUT FILENAME**: `message.txt`
- **GENERATION TIMEOUT (SECONDS)**: `30`
- **CACHE TTL (HOURS)**: `72`

### Automated CI / GHCR Publication
A GitHub Actions workflow (`.github/workflows/docker-publish.yml`) automatically builds, tests, and publishes the container image to GitHub Container Registry (`ghcr.io`) upon pushing to `main` or tags:
- **Registry**: `ghcr.io`
- **Image**: `ghcr.io/azariyasmekonen/fidel-telegram:latest`

### How the Generator Works
The container runs with environment variables supplied by the CTF platform:
- `FLAG`: Dynamic participant flag (e.g. `AdwaCTF{...}`)
- `USER_ID`: Unique participant or team identifier
- `OUTPUT_FILENAME`: Name of output file inside `/output/` (defaults to `message.txt`)
- `OUTPUT_DIR`: Target directory (defaults to `/output`)

When executed, the container executes `/app/src/generate.py`, encrypts the telegram text containing the dynamic flag, and writes the output file to `/output/message.txt`.

### Building the Generator Image
```bash
docker build -t ghcr.io/azariyasmekonen/fidel-telegram:latest .
```

### Testing the Generator Locally
```bash
mkdir -p ./output
docker run --rm \
  -e FLAG="AdwaCTF{SAMPLE_DYNAMIC_FLAG_1234}" \
  -e USER_ID="team-42" \
  -v "$(pwd)/output:/output" \
  adwactf/fidel-telegram-generator:latest

# Verify generated file
cat ./output/message.txt

# Verify with solve script
python3 solve/solve.py ./output/message.txt
```
